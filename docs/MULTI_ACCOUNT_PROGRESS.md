# 每家一到四张号码与总四张配置

2026-10-02。老板明确需要三张、四张卡，也包括同一家运营商三张或四张。先读取 TECH_LOG 与 MULTI_ACCOUNT_REVIEW，复用已有 Flutter、AndroidX MULTI_PROFILE 和 iOS 独立 WebsiteDataStore 参考；没有新增依赖或复制另一套账号架构。号码可以来自其他手机，配置数量不受本手机物理 SIM 卡槽数量限制；APP 不读取 SIM 卡。

账号主 ID 保持 `mobile` / `broadnet` / `unicom` / `telecom`，扩展副账号为 `_2`、`_3`、`_4`。旧主账号默认 Profile、旧 `_2` 独立 Profile 名、查询记录及广电安全存储键均不改名、不搬迁。新增副账号的 Profile 名继续为 `liuliang_<accountId>`，查询、超时、备注与快照各自按 ID 存取。JSON 白名单只接收这十六个合法 ID，不接受 `_1`、`_5`、`_02` 或与运营商不一致的 ID。

`CarrierAccounts` 保留 `carrier_accounts_v1` / schemaVersion 1，新增可选 `enabled` 字段，旧记录缺失时按启用恢复。收起副卡或减少数量只设 `enabled=false`，保留该记录的备注、手填号码、快照与网页登录资料。增加数量时按原 ID 恢复隐藏账号，再创建缺失 ID；隐藏中间卡不会把 `_3` 改名成 `_2`。历史每家最多四条、合计最多十六条；只有所选运营商的启用账号计入最多四张展示与查询。`visibleAccounts` / `visibleCount` 都过滤 disabled 记录，后台及系统桥接需沿用该结果，不能遍历全部历史记录当作当前卡。

选择页移除双击加入的交互，运营商下直接展示“1 张 / 2 张 / 3 张 / 4 张”数量选项，超过剩余总配额的选项禁用；已存在过量配置时也禁止保存，允许先减少数量。取消整家只隐藏运营商，保存数量不会删除其他运营商的历史。说明文字和汇总显示总张数，窄屏大字使用 Wrap 换行。每张副卡仍需确认系统独立 Profile 能力，无法支持时不创建共享登录态的假卡。

选择页新增 `onAccountCountsChanged(Map<Carrier,int>)`，`accountCounts` 是明确的每家数量。`onContinue(Set<Carrier>)` 保留既有选择页契约，由 main 捕获对应 counts 并以 `_applySelection(..., accountCounts: ...)` 保存。`onAddSecondAccount` 仅保留旧外部组件兼容字段，main 与新交互不再依赖它。首次选择和管理页共用 counts 验证，保存必须每家 1–4 张且总和不超过四张。

main 的“清除本地连接”将各运营商 slot 1–4 全部枚举，清理对应快照、连接标记、后台认证标记与广电安全存储，Profile 是否曾存在也检查 `_2`、`_3`、`_4`。原生 Profile 名白名单、iOS 固定 UUID 和后台过滤由集成分工同步扩展；原有 `_2` UUID 必须保持不变。数量变更和收起不执行这些清理，只有用户明确清除才删除登录资料。连接和刷新入口也拒绝 enabled=false 的账号。

同次按查询代理契约为电信 onLoadStop/inFlight 显式执行 `telecomRenderedCaptureScript`，让提前到达而未被接收的官网 DOM 在重新加载后再扫描。按钮查询仍 loadUrl 官网页面后读取，保持联网查询语义，没有把旧 DOM 重读当成刚联网，也没有假设移动 getNewMarginInfo 含话费余额。

新增/更新核心测试验证四张同家稳定键、十六条隐藏历史与混合总四张、减少和重加保留备注及中间 ID 空位、旧 JSON 兼容与非法 ID 拒绝。流程测试覆盖同家三/四张保存重启、混合三/四张、Profile 不支持拒绝以及管理减量/恢复；选择页测试改为明确数量和总量禁用。SDK 按根代理串行规则执行，此阶段未独立运行 Flutter/Android。布局测试与 mock 能力检查不代表真实四个号码登录及余额已完成验证，最终验收结果由 TECH_LOG 补充。

本轮收尾把官网 Shell 的查询操作改为可见“查询流量”文字按钮，最小高度 48dp。窄屏分行保留标题/收键盘等操作，宽横屏同排；不会只有说明中有“查询”却只显示放大镜。联通提供随机密码登录说明，保留官方 DOM 与 UA，原生初始 100% 显示、允许双指缩放及 Android 缩放按钮，没有自动发送短信。三四卡首页使用随文字自然增高的紧凑页头、缩小卡间距，分类/时间/余额与48dp操作仍可见；套餐与通话明细可展开。新增实际四个同家账号渲染与独立 `_4` 刷新测试，截图目标为 `artifacts/dashboard-four-accounts-demo.png`，数据明确为 DEMO，另覆盖320px大字三/四卡操作。

连接动作新增明确“打开官方验证页”状态与35秒加载期限，官网进入登录页后显示待验证，登录返回查询页后开始受控余额查询；空白页回调不取消正常连接加载。电信 SPA 从登录 hash 返回精确官方查询 route 时显式 rescan该次导航DOM并启动35秒边界，不要求一定出现onLoadStop；页面关闭时只对已在合法官方查询页的账号继续受控查询。既有查询超时同样保留旧余额和原时间，未把读取旧 DOM 冒充新联网。低量通知 ID 改为 `carrier.index * 4 + slot`，十六个已知账号互不覆盖；单测新增ID唯一性、联通设置以及无网页回调连接超时保留旧金额/时间。
