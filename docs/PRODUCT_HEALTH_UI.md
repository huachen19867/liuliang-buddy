# 查询状态页面

`app/lib/ui/query_health_screen.dart` 用于按账号查看查询健康状态和已接通的恢复入口。页面只接收 `QueryHealthReport` 白名单诊断值，不读取手机号、官网响应、Cookie 或 token；页面上的恢复按钮只转发账号 ID 与 `QueryHealthAction`，实际操作由应用根状态处理。

每张账号卡分别表达正常读取、登录过期、官网访问错误、部分字段未读、后台暂停、尚未连接和正在检查。说明文字来自诊断模型。只有模型给出真实可执行的恢复动作时才显示按钮：重新登录、重新查询、查看套餐明细或打开后台刷新设置。正常和检查中的账号不显示无用刷新按钮；空操作不会生成按钮。

卡片始终将最近有效数据时间标为“上次有效数据”，并将新的尝试时间单独标为“最近尝试”。失败状态保留旧时间，避免读者把上次成功误认为当前查询成功。尚无成功数据时明确显示“尚无成功记录”。页面头部只读展示应用版本和自动刷新间隔；后台区域展示根状态提供的最近结果与结束时间，不提供未经接通的开关。Android 调度限制和 iOS 不支持的说明由诊断模型如实提供。

界面沿用海滨温泉配色、运营商标识和圆角卡片，单列适配窄屏并允许内容滚动。测试位于 `app/test/ui/query_health_screen_test.dart`，覆盖四种主要故障、恢复动作与账号绑定、保留的有效数据时间、版本/刷新间隔、320×640 大字多卡布局以及无历史数据状态。最终 Flutter SDK 检查由根任务串行执行。
