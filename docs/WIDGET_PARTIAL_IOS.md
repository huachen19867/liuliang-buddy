# iOS 小组件电信部分套餐预览

2026-10-02。沿用 `docs/IOS_WIDGET.md` 的 schema 2 白名单快照与既有电信部分结果口径；参考源码已在 `references/ios-home-widget/`，本次没有新增依赖或重复下载。

电信总量无法确认时，小组件可以显示一条数值可读的套餐余量作为提示。Runner 只传 `trafficReadableCount`、`trafficPendingCount`、`previewRemainingBytes` 和 `previewUnlimited` 这四个展示字段，不传套餐名或运营商原始字符串。单项有限余量格式为“单项约 X.XX GB”，不限量格式为“单项不限量”；摘要标签为“部分套餐”，状态行显示“N项可读 · M项待确认”的实际计数。

Widget 仅对电信启用部分预览，并要求状态属于既有状态集合且不是 `notConnected`、`queriedAt` 在既有范围内并且不晚于当前时间五分钟以上、主总量 `primaryValue` 缺失。可读数和待确认数各为 1–200 且合计不超过 200。有限单项必须有不超过现有数值上限的有限非负字节数；不限量单项必须明确标记为不限量且不带字节数。布尔值、分数、负数、超限计数和无效余量不会成为部分结果。主总量已有数值时，既有总量展示优先。`success` 状态先显示过期提示，再显示部分计数；加载、认证失效和错误状态保留上次单项预览并显示原有状态提示。

加载、认证失效和查询错误时，有效的上次单项预览与标签继续保留；状态行仍优先显示“打开应用查看”“需打开验证”或“保留上次记录”，不显示新的部分计数。没有有效查询时间时仍显示“待查询”，未知状态仍按原规则归为错误。旧 schema 2 缓存没有这些可选字段时继续解码。

`app/ios/Tests/TrafficSnapshotTests.swift` 增加有限与不限量单项、计数边界、总量优先、无查询时间、失败状态保留和 Codable 往返覆盖。当前 Windows 工作环境没有 Swift/Xcode，本次没有运行 Swift 测试或编译；需由 macOS CI 验证 Shared 模型及 Widget 扩展构建。合成模型覆盖不代表真实电信账号或 iPhone 桌面布局验收。
