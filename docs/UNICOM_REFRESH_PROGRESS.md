# 联通刷新转圈排查与前台状态修复

2026-10-01。依据老板提供的联通登录后刷新转圈反馈，先复查 `docs/TECH_LOG.md`、既有 `references/carrier-public-deep/` 官网页面摘录、`docs/UNICOM_TELECOM_RESEARCH.md`，继续让官网自行发起 `userinfoE5query`，没有引入 APP token、重复请求或用户凭证。本轮没有真实账号，不能确认反馈手机上的唯一触发条件。

代码中有可证实的登录返回缺陷：查询转到联通登录页时虽清除了进行中请求，却保留最后请求时间。完成登录返回 E5 页后的自动刷新在 30 秒内被节流退出，而回调又提前移除了等待登录返回标记，官网自然到达的响应可能无法进入解析。现在登录页回调解除该账号节流；加载失败也解除，以便及时重试。节流按账号独立，两个同运营商号码互不影响。

查询超时改以进行中请求标记判定终态，35 秒后清除标记并把加载状态变成可重试的错误。此前如果前台恢复从存储覆盖了内存状态，超时回调可能因状态不再是 `loading` 提前退出，留下不能再次刷新的进行中标记。恢复时不覆盖正在查询的账号；历史 `loading` 快照归一化为错误，避免重启后没有计时器却继续转圈。前台恢复读到真正的后台成功记录则保留成功状态和原查询时间。

官网响应页校验继续限定在各家余额页。联通允许 `/e5/index.html` 与 `/e5/query.html` 之间的合法切换以及查询参数变化，拒绝登录路由、营销页或仿冒域名；移动与广电只允许各自确定的查询页路径，电信仍要求精确 Home hash。这样不会因官网无关 URL 变化丢弃真实余额响应，也不会放宽登录页回调门禁。

移动官方页面新增“登录遇到问题？”说明。如果网页不提供短信或要求人脸验证，建议先在中国移动官方 App 完成验证；明确告知 App 验证不会自动同步本应用网页登录，网页仍无法登录时该号码暂不支持自动查询。官方下载入口采用已有官方来源 `https://www.10086.cn/cmccclient/`，不自动跳转、不声称任何卡型或验证后必能查询。

定向 Flutter 测试 16 项通过，覆盖登录返回解除 30 秒节流、双账号节流独立、四家当前页门禁、重启遗留加载态、前台恢复保留后台成功；`flutter analyze` 无问题。此验证只覆盖本地状态与合成条件。真实联通官网登录后的页面路由、响应、等待时间及账号套餐仍需在老板手机上复测；如果仍失败，应记录当前官方页面 URL 路径、APP 显示的错误文案和大约等待时长，不需提供手机号、验证码或 Cookie。
