# 套餐手动分类设计与集成审查

2026-10-02。需求来自用户提供的反馈截图：在套餐明细弹窗里选择通用或定向，以修正自动识别。先阅读 `TECH_LOG.md`；复用本地 `references/FlowLite/README.md:29–37` 的个性化分组说明，未重复下载。FlowLite 未发现许可证，仅参考允许用户修正默认分类的产品思路，独立实现，不复制其移动套餐包或清除计数代码。

## 数据和界面契约

`TrafficBucket.kind` 保留解析器的自动分类，`manualKind` 只允许通用、定向或空，展示和统计使用 `effectiveKind`。用户可以恢复自动；手动选择不改变原始余量、单位、查询时间或是否不限量。未知单位即使手动设成通用也不能产生可用数值或低流量提醒。

覆盖独立保存在 `traffic_classification_overrides`，按稳定账号 ID 和唯一的 trimmed 套餐名匹配。两张同运营商卡不得共享覆盖，重排套餐后覆盖仍有效。汇总行、同名歧义行、无名称行禁用编辑并显示原因，防止把混合口径或多个包误标成通用。套餐改名后不猜测继承，恢复自动识别。

详情回调为 `Future<bool> Function(String, TrafficBucket, BucketKind?)?`。保存前重新确认账号、当前套餐及可编辑条件，不能拿弹窗打开时的旧行直接覆盖最新查询结果。成功落盘才展示成功；失败保留原选择并可重试。

## 主流程接线

`main.dart` 的 `_putSnapshot` 是前台快照的共同入口，适合统一 `apply(account.id, snapshot)`；启动恢复覆盖应早于恢复快照。恢复到前台的 `_reloadBackgroundSnapshotsAndRefresh` 先读取覆盖，再导入后台记录。`apply` 必须先清除快照中可能存在的旧 `manualKind`，然后叠加独立覆盖，独立 key 才能保持唯一权威。

用户保存覆盖后，应重新套用当前账号最新快照并立即发布桌面组件，不发起无必要的运营商查询。存储操作复用 `_store` 串行队列，既保留其他账号覆盖，也避免连续点选的前一个写操作盖住后一个。

`_notifyLowTraffic` 现有调用传入解析所得的局部 `snapshot`，仅修改 `_putSnapshot` 并不足以改变提醒统计；提醒入口也必须应用当前覆盖或读取当前已处理快照。手动通用统计应在通知和详情中说明“按手动分类统计”，不能称为运营商提供的通用分类。纯手动调整不更新运营商查询时间。

改备注保留覆盖；账号规范化后的号码改变时清除此账号覆盖，避免新的号码继承旧号码的同名套餐判断。减少可见卡数属于隐藏，保留覆盖以便恢复；清除全部连接/账号资料时清除整个覆盖 key（包括隐藏账号）。号码比较使用更新前后的规范化 `phoneNumber`，避免 null 与空串误判。

## 后台和组件

后台只读取覆盖，不写覆盖 key。网络结果返回后已有 `prefs.reload()`；以最新覆盖处理成功或保留的旧快照，在最终生成组件前再次 reload 并对所有当前快照应用覆盖。前台也必须在恢复时重新叠加权威覆盖，使后台较早保存的嵌入值不能复活已恢复自动的分类。

SharedPreferences 多引擎读取/写入不是事务：在后台最后一次 reload 和返回 native widgetPayload 之间仍有极小竞态窗口。最终发布若要完全避免短暂旧展示，需要 native 协调任务版本或单一发布者；本轮不能仅凭一次 reload 宣称原子一致。独立 key 不被后台写入保证用户选择不会丢失，后续前台/后台重新发布会收敛。

首页摘要、通用/定向组和 widget payload 均应采用 effectiveKind。Android `WidgetAccountDetails.safeLabel` 有标签白名单；`TrafficWidgetProvider` 的低量判断只识别原有“通用剩余”。最小实现保持既有 primaryLabel，手动属性在详情/通知解释，避免增加标签后被原生降级成“余额待确认”。若需要组件也展示手动标识，应新增明确字段并贯穿 Android/iOS 接收、保存和渲染，不以改标签字符串替代完整接线。

## 集成后的有限复核回执

2026-10-02，主任务报告完整 Flutter 244 项及 analyze 通过后，再只读核对 `_classifyTrafficBucket`、`_putSnapshot`、恢复入口、`_editAccount`、清资料与后台最终 apply。未发现需要阻断本次发布的分类接线错误。分类保存进入既有串行存储队列，校验账号启用状态、打开弹窗时的号码和当前套餐是否仍唯一，落盘成功才更新显示；apply 保留原始 kind 并清除过时 manualKind。号码以更新后的规范化字段比较，备注不影响覆盖；清资料等待队列后删除整个分类 key，避免稍早的保存复活分类。

提醒入口现已重新 apply，且手动通用时有“含手动分类”说明。后台最后一次 reload 后对所有账号按最新覆盖重新 apply，再生成 widget payload；原生兼容标签保持不变。后台保存的原始快照可以不包含最新手动分类，因为独立覆盖 key 为权威，前台恢复和后台发布均重新叠加。相关流程测试源码覆盖立即同步、账号隔离、重启/恢复自动、查询中改分类、改备注及换号码拒绝旧弹窗。

保留既述 SharedPreferences 非事务发布窗口；另外号码编辑采用先清覆盖再写号码的保守顺序，在本机存储第二次写入失败时可能只清除了原号码的分类，但不会把旧分类带给新号码。此异常会提示保存失败，不构成错账号分类或认证泄露。此轮复核没有重跑 SDK、扩大功能范围或改动生产代码。
