# 运营商选择与旧版迁移设计

首次使用先选至少一家运营商，完成选择前不创建查询页面、不启动前台定时查询、不向桌面卡片发送旧余额。`app/lib/data/carrier_selection.dart` 是纯配置模型，完成态至少有一个且去重，序列化以 `Carrier.name` 保存 `schemaVersion=1`。目前支持的运营商仍只有中国移动和中国广电；该模型遍历 `Carrier.values`，后续加入新枚举值时不必改旧版迁移清单，但新运营商的登录、解析、页面与布局仍需分别实现和验证。

新配置尚不存在时，才遍历所有当前 `Carrier.values` 的旧 `connected_<carrier.name>` 布尔标记来迁移。曾实际连接一家就只选那一家；两家都连接过才选两家；都没有连接过则进入首次设置。缓存余额不能代替连接标记。新配置已存在但损坏、未知值或来自更高版本时，安全回到未完成态，不重新读取旧标记，以免把已隐藏运营商重新启用。迁移结果应立即按当前版本写回。

根流程应把选择作为查询授权门禁。定时刷新、手动刷新、桌面点击、WebView 创建、官方响应回调和首页投影均检查 `selection.allows(carrier)`。`queryableCarriers(connected)` 与 `visibleSnapshots(snapshots)` 提供纯过滤能力；即使旧的 `_connected` 标记还在，隐藏运营商也不会被查询或显示。迟到的网页回调还须受 `_generation` 与当前选择共同限制。

更改选择时先暂停查询、提升世代编号、取消受影响的超时计时器并卸载隐藏运营商页面。由于原生 AppWidget 有独立的展示缓存，应先清空它，再保存新选择并只发布当前选中运营商的快照；否则桌面可能短暂留着隐藏卡余额。隐藏运营商的本地查询记录、`connected_` 标记与已有安全会话继续留在本机，方便重新选中后恢复；它们不进入首页、查询队列或桌面 payload。旧网页回调仍须由世代编号和选择门禁阻断。用户主动执行“清除数据”时才删除全部记录与会话。选择未完成时，桌面缓存保持清空。

当前桌面组件支持移动和广电的零卡、单卡与双卡显示。schema 1 的 `selectedCarriers` 名单只包含已选择的名称；旧 payload 若没有此键则按旧双卡行为处理。隐藏卡的余额、状态和查询时间都不传给 Native，也不会写入其展示缓存；空名单显示选择提示而不展示卡片。将来扩大到四家时，桌面组件的动态布局、Native 解析和通知路由仍须同步扩展，不能只向 `Carrier` 枚举追加值。
