# 本机号码一键登录研究（2026-10-05）

老板提出参考官方 App 的本机号码一键登录，减少广电约三日后重新收验证码的操作。结论是可以借鉴登录体验，但号码认证与营业厅查询授权是两层能力。当前公开证据不能证明给本应用申请一个认证 SDK，就能得到任一家营业厅的流量、话费查询会话，更不能使已有营业厅会话长期有效。

## 已取得的官方证据

中国移动 [号码认证官网](https://www.cmpassport.com/) 明确区分 APP 一键登录、H5 一键登录和本机号码校验，后者返回号码是否为本机号码的结果；官网列出的用途包括第三方应用注册、登录、号码绑定。页面不是营业厅余额授权文档。原文已保存到 `references/one-click-login-20261005/mobile.html` 和 `mobile.txt`，URL、下载时间和 SHA-256 在同目录 `index.json`。

中国电信 [天翼账号开放平台](https://id.189.cn/) 明确说明“为合作伙伴提供一键授权本机号码登录”，并以京东、新浪微博、支付宝的注册登录为例。其“运营商查询”只是一个产品名称，不能凭名称解读成流量话费查询。已保存门户和公开免密认证产品页，未登录平台注册。产品页提示免费体验入驻，不等于正式调用永久免费；本轮没有获得可核验的正式报价、套餐或免费额度。

联通预期开放平台入口 `https://www.uniaccount.com/` 本轮匿名访问超时，因此不把 SDK 版本、入驻条件和价格当已验证事实。老板补充的广电官方 App 截图已明确显示“本机登录 / 短信登录”、192 掩码号码、“由中国广电提供认证服务”和一键登录，广电原生本机认证功能已经证实。之前桌面官网短信页只能说明该网页入口，不能据此断言整个广电没有本机认证。仍待核实的是能否合法复用到本应用的公开 H5 入口、第三方 SDK 及营业厅授权协议；不能从移动与广电共建共享网络推导两者身份令牌互通。

## 广电官方 App 与公开 H5 登录分界

从广电官网 [客户端下载页](https://www.10099.com.cn/client-download.html) 的公开版本响应找到正式 App Store 入口 `https://apps.apple.com/cn/app/id1643456835`，其开发者隐私政策链接指向 [广电 App H5 隐私政策](https://app.10099.com.cn/h5-app/#/pages/detail/serviceAgreement/index?xyId=xy20220613000017)。已用匿名浏览器正常读取这份政策和公开网页脚本，无须安装 APK 或提供号码。公开版本元数据为 2.3.0、更新日期 2026-09-18。

政策公布腾讯 X5、银联、支付宝、微信、旷视 OCR/活体等第三方 SDK，但没有列出可供本项目申请的广电本机认证 SDK。该清单不能证明广电自己没有认证实现，尤其截图已经证明有本机认证。此处只记录“未取得第三方接入文档”。

公开主脚本 `app.1790235502569.js` 和首页 `11.1790235502569.js` 给出直接分界：浏览器 UA 包含 `CBN` 时，登录操作调用 iOS `window.webkit.messageHandlers.nativeCall.postMessage({type:'login'})` 或 Android `window.android.nativeCall(...)`；普通浏览器改为显示网页登录弹窗，或转到 `/pages/home/index?needLogin=1`。公开 `2.1790235502569.js` 中该网页弹窗展示“手机号验证登录”、手机号、验证码、协议及“立即登录”，提交的是 `loginPhone` 与 `loginPassWord`。这条已找到的公开 H5 分支没有复现截图的本机一键登录 UI，不能只将 URL 换为 App H5 就声称已接通本机认证，也不能伪造 UA 把本应用变成官方原生宿主。

此次普通首页的两次匿名浏览得到空白显示，但成功取得其官方按需脚本；因此以上是官方源码分支证据，不宣称网页首页已完成可交互真机验证。隐私政策页面已正常呈现。`m.10099.com.cn/` 根路径返回 403、`h5.10099.com.cn/` 根路径返回上游 404，仅代表这两个根路径，不能据此否定其他公开 H5 路径。

当前没有找到一个能直接在本应用 WebView 中合法调用广电原生本机认证、再带回营业厅会话的公开入口。可继续研究正式开放接口或官方允许的回调；官方 App 内完成一键登录不会自动把其私有会话同步给本应用。此结论承认原生功能已证实，同时保留第三方授权与公开网页登录接入仍待核的边界。

## 移动官网已经有可复用的一键登录流程

复用已有 `references/allowances/mobile-10.js`，来源为移动官方公开登录脚本 `https://wx.10086.cn/website/js/new/signIn/indexMin08182026.js?v=08182026`。仅在隔离的无网络 Node VM 中计算字符串字典，并阅读调用结构，没有运行完整网页逻辑、发起取号或登录请求，也没有复制官网认证代码。

官网先由 YDRZ 生成签名请求，再调用同站 `../oneKeySignIn/sign` 获取服务器签名，经 `YDRZ.getTokenInfo` 取得 token、userInformation 和掩码手机号。正常交互分支展示掩码号码及协议，用户点击同意后，再把认证结果提交给营业厅自己的 `../oneKeySignIn/info`；该接口返回成功才进入营业厅登录成功回调。这直接说明号码认证 token 与营业厅会话之间还有运营商自己的服务端兑换步骤。官网自己的 appId 与签名上下文不属于本应用的第三方授权，不能复制使用或伪造。

同一脚本中“三天免登录”仍由官网 `checkCtrol` 字段控制，不能通过本机一键认证变成永久免登录。一键认证减少重新验证时的输入，并不承诺延长服务器会话。官方 App 登录后的私有会话也不会自动进入本应用 WebView。

### 现有公开 H5 入口与触发条件

已有正式入口 `https://wx.10086.cn/website/bind/bindAccount/new` 的匿名归档 `mobile-2.html` 给出 `channel='10086'`，并加载中国移动 `www.cmpassport.com/NumberAbility/jssdk/jssdk.min.js`。普通渠道 10086 在页面就绪时即尝试官网自己的取号流程，不需要应用附加特殊参数或注入调用。源码排除普通触发的渠道为 30006、30007、10003、30011；微信渠道 10001/10008 且 wx 对象存在时先取网络类型，在 Wi-Fi 下不启动该分支。默认渠道直接调用 SDK，由 SDK 和运营商判断网络是否支持，不能从这一点保证 Wi-Fi 可取号。

取得 token、userInformation、msisdnmask 三项后，正常分支才展示已有的 `.onekeyLoginPop` 掩码号码授权框，并检查用户自行勾选的协议。取号失败保留短信流程。URL 的 `noPerception=1` 或 `loginauth=1` 会进入自动提交或重定向分支，本应用不应添加这两个参数；它们不是普通用户主动确认的一键入口。现有 WebView 已打开该公开页面，因此增加同 URL 按钮本身不会提升取号成功率。可做的是解释如何使用官网弹出的本机号码入口、正确呈现协议和失败回退，再验证真实设备是否出现兼容问题。

三卡、四卡是本应用中的账号数量，不能让同一手机数据连接自动认证全部账号。一次网络取号通常对应当时用于移动数据的 SIM；多次点击可能始终返回同一张卡。必须由用户核对官网掩码号码是否匹配当前目标账号，不匹配时取消并使用其他官方验证方式，不能把重复认证同一号码记为多个账号已成功连接。

## 当前可实现范围和接入前置条件

当前可实现的合理范围是保留营业厅官方页面的完整登录流程，兼容官网本身展示的本机号码授权入口，让用户在官方页完成操作并继续捕获正常查询结果。移动已有该流程的源码证据，但是否在此 WebView、手机网络、SIM 和账号组合上可用，仍须真机自愿授权验证；不能添加一个尚未接通的“一键登录”按钮。双卡手机的默认数据卡可能不是用户正在查询的号码，多账号场景必须核对授权页掩码号码，不能自动替用户确认协议或切换号码。

若另行接入面向第三方的原生 SDK，需先取得本应用在平台上的正式应用资格及配置，核对 Android 包名/签名、iOS Bundle ID、各端 SDK 支持范围、appId、服务端密钥保管和服务端验号/兑换接口。是否要求企业主体实名认证、应用备案、上架证明以及具体审核材料和费用，应以当前平台控制台和正式协议为准；本轮没有登录后台，不能把这些待核条件表述为四家统一规则。当前项目也未提供已获批的这类应用配置及服务端，因此本轮不接入 SDK、不注册账号、不购买套餐。

即使完成上述第三方号码认证，还必须另有运营商明确允许的营业厅授权接口、回调或查询 API，才能满足本项目的流量话费查询目标。现在缺少的是这层授权证明，而不只是 SDK 接线。没有这层能力，新增 SDK 只能证明用户控制该号码，不能解决广电服务器使营业厅会话失效的问题。
