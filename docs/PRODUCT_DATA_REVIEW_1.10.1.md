## 已证实问题与有限修复

审查发现缓存流量恢复的数值门禁弱于展示合计。原 `TrafficBucket.fromJson` 接受任意 int，包括负数；原 `CarrierSnapshot._sumGeneral` 只判断空值和不限量，直接相加，没有负数和有符号 64 位溢出检查。`traffic_summary.dart` 的 `_completeSum` 已有这些检查，因此同一异常快照可能得到不同的模型通用余额和界面摘要。使用恢复缓存的负数，或两条总和超出 `9223372036854775807` 的通用行，即可由代码推导出问题，不依赖猜测运营商字段。该 getter 也被低流量判断调用，不能容许异常金额成为有效通用余额。

向根任务说明后获得明确修改授权，只修改 `app/lib/data/models.dart`。通用 getter 现在拒绝负值和会发生 64 位溢出的合计。缓存每个剩余/总量值必须为非负范围内 int；非整型、负数或越界成为未知。若剩余大于同一行总量，两项都变为未知。明确布尔不限量标记优先，有限数值置空；字符串形式的旗标不被升级为已确认不限量。

无效流量行保留名称、分类和原始显示内容，不能删行后将其他套餐部分相加伪装为完整分类。独立总量坏值不破坏有效剩余，真实零值仍是零，查询状态与原查询时间不被刷新。新增 `app/test/data/traffic_bucket_cache_test.dart` 共 8 项回归，覆盖异常缓存保持占位、总量独立缺失、零值往返、剩余超过总量、不限量数值冲突、直接构造负值、精确 64 位上限/溢出，以及失败旧时间保留。由根任务统一格式化、analyze 和运行测试，本子任务不报告未执行的 SDK 结果。

## 单位、余额与分类结论

移动的公开参考明确 `01=分钟、02=条、03=MB、04=GB`，当前实现按字段单位分别解析，拒绝缺失单位，不照搬上游默认 GB 和缺值默认零。`totalInfo` 是官方总览，已排除“其他流量”分类相加。语音有可用官网汇总时优先汇总，不叠加可能共享的套餐。`getNewMarginInfo` 没有经确认的独立话费余额，当前不使用实时费用或消费字段猜余额，这个能力缺口应继续如实说明。

广电 H5 公开脚本把 `busiType=5` 的 `highFee/balance` 除以 `1024²` 显示 G，因此这个精确 H5 路径用 KB 有依据；语音和短信不参与流量。外层 `701` 和内层业务成功码分别检查，原始与官网解包后的结构兼容。旧小程序解析入口缺少统一单位证据时仅保留原值，与 H5 分开，不应把“两个端点都叫 qryUserRes”当作会话及单位互通依据。名称明确通用或定向才归类，其他仍保持用途未知。

联通 E5 官网由 `commonsFormat.getFlow` 展示 MB 汇总，单项命名“官网套餐余量”，不推断为通用。官网不限量标志的 JavaScript truthiness 是现有官网实际显示行为，保持与 App 精确文字不限量判定分开，不能统一成对所有运营商的宽松标志规则。App 端点套餐保留总量和剩余，真正缺剩余才以总量减已用，零剩余不被覆盖。资源汇总不叠加详情，跨列表相同行去重，同名不同值保留未知占位抑制合计。App 独立话费仅 `accountBalancenew.htm` 的 `curntbalancecust` 元值可用，零和负余额合法；费用失败不破坏成功套餐。

电信目前读取公开 Account 组件已用/总量带单位的显示值，支持 MB/GB 各自换算再相减，并明确标为估算。官网原节点 `#balanceModal #mobileBalance` 同时检查“余额”和“元”标签，不能把 `mobileTimeBalance` 当前费用当余额。舍入、共享和重叠关系仍提示以官方套餐规则为准。流量默认用途未知，不将“国内流量”直接等同于通用。

## 失败、未知与不限量行为

前台 `_finish` 与后台刷新失败分支只替换状态和失败说明，保留之前成功的流量、余额及 `queriedAt`。展示摘要在有旧查询时间时可继续显示上次记录，模型通用 getter 只对成功状态输出可用于提醒的余额。这是正确区分“旧记录可看”和“本次成功”的行为，不应失败清零或更新旧记录时间冒充刚查到。

多个未知用途套餐不应擅自当通用。联通整个快照只有一条未知且单位/金额可靠的套餐时，可显示“套餐余量”及其套餐名称；如果另外存在定向或其他行，不把单项当全部合计。分类内有缺余额、缺单位或不限量时，有限数字合计不会填零。显式不限量可以展示不限量状态，但不会由零总量、负数或异常大数推断不限量。

有一项旧缓存显示一致性待根任务决定：`summarizeTraffic` 的通用主位分支目前只检查 canonical byte 数值，分类格另外要求 `rawUnit` 已确认；旧缓存含通用 bytes 但缺 `rawUnit` 时主位可能有数字而分类格未知。当前各生产解析器确认 bytes 时都会填写单位，所以未发现真实响应触发路径。此处没有私自修改 summary 或清理已有历史单位，不为理论一致性破坏兼容。

广电和电信套餐明细的共享或重复可能性没有真实成功响应证据，不能仅凭名称相同就删除官方行。当前广电摘要明确为已查询“套餐明细合计”，电信为“套餐估算余量”，不宣称是可任意使用的通用额度。本轮没有新增未经证实的 package id、共享标志、余额字段或省分假设。
