# 四家查询与多卡状态复核（1.10.1）

2026-10-02，老板说明暂时没有联通卡，并授权参考互联网实现继续优化产品。本次为有限范围的静态复核，覆盖四家查询、前后台结果接收、多卡隔离、清除与旧数据时间。先读 `TECH_LOG.md` 和 `references/README.md`，复用已下载的 ChinaMobileMonitor、ChinaUnicomMonitor、ChinaTelecomMonitor、FlowLite、10099-Tracker、运营商公开页面归档及 Google WorkManager 参考，没有重复下载、请求真实账号或新增认证协议。本文件由只读审查子任务新增，生产修复与最终测试由根任务记录。

## 已发现的有限修复项

后台联通 App 会话第一次读取已通过有三秒期限的 `_readUnicomAppSession` 隔离错误，但查询完成后的 `currentRaw` 再读仍直接等待安全存储；续期写入也直接等待。该位置若抛错，会跳出整轮后台任务；若插件不返回，会耗尽原生 Worker 的四分钟窗口，使其他卡片失去本次刷新机会。建议第二次读取复用相同 helper，失败只跳过本账号，轮换写入加期限并按账号处理异常。不能把读取失败当作会话版本仍相同继续覆盖。

后台 WebView 的 `trafficResponse` 回调使用完整 `currentPage == capturedPage` 判断，前台则使用共享的 `isCarrierResponsePageCurrent`。因此同一个合法查询页在请求开始后只改变查询串或 fragment，前台允许的返回会被后台丢弃，直到超时。建议后台直接复用共享策略，同时保留 `isCarrierResponseAllowed` 的来源与端点校验。该策略对电信仍要求完整页面相同，不扩大电信接受范围。

后台 `_queryInHeadlessWebView` 已限制启动十五秒、等待结果四十秒，但 `finally` 中的 `webView.dispose()` 没有期限；网页内核失灵时可以阻断整个串行账号队列，直到原生四分钟强制销毁引擎。建议清理等待加短期限，继续保持 `acceptingResponses=false`，不接受迟来的回调。广电安全存储备份读写也应采用有界等待，避免查询期限之外再出现无界等待。这是异常内核/存储故障下的可达阻塞点，不是已观察到真机必现。

上述发现已即时交给根任务；本文不把建议自动写成已修复，具体落实与验证应以最终变更和技术日志为准。

## 四家适配结论

移动仍使用官方 `getNewMarginInfo` 结果，流量、通话、短信识别单位，官方汇总不与分项重复相加。该响应没有经过确认的话费余额，本轮不从名称相近字段猜金额。官方 App 身份验证与本应用网页登录不同步，旧参考也不能证明第三方可直接复用手机系统校正接口。

广电优先官网解码事件，原始事件须单独证明业务成功或认证失效；前后台共用 `shouldApplyBroadnetResponse`，避免原始密文覆盖已识别数据。保存的会话有七天期限、未来时间拒绝恢复，WebView 仍由官网执行认证，不引入参考项目的密码或请求签名实现。

联通 E5 官网与 App 查询保持独立认证。App 会话按账号安全存储，Cookie 归属只是用户确认，token 续期要求服务端完整号码和新 Cookie。此前发现的编辑号码在途回调和无新 Cookie 续期问题已交根修复；本轮阅读版本可见号码门禁、一次续期和低流量通知接线。没有真实联通卡，不能以合成测试声明登录、风控或全国套餐查询成功。

电信按官方 Account DOM 的明确单位估算余量，继续标为估算；仅靠前台已有 sessionStorage 和渲染内容，后台明确排除。参考 ChinaTelecomMonitor 的 App 协议不能自动解决当前网页会话恢复，不扩大到未经验证的后台认证。

## 多账号、清除与时效

账号使用稳定槽位 ID，额外网页账号采用独立 Profile，App 模式按账号独立 secure key。当前源码在选择变化和清除时递增 generation，停止旧查询；清除先持久化 pending 状态，再关闭后台、清理可见及隐藏槽位的会话和记录，失败时保留清理门禁。未发现需要为了本轮修复改动槽位结构或批量删除工作区资料的理由。

原生 Worker 在应用可见、工作取消或配置 revision 变化后停止接受结果；Dart 在写入前再次检查任务、账号启用状态及号码，App 会话另比较原始安全存储版本。前台恢复后台记录时跳过正在查询的账号，不把网络失败改写成新查询时间；认证失效保留上次成功余量、余额及时间。成功时间只在解析接受的新响应上生成，界面和桌面均保留旧记录状态。

当前有限复核未发现需另造四家通用登录或重新设计全部缓存结构的证据。优先完成上述后台等待边界与共享页面策略，再运行已有针对性回归和全量检查。由于没有真实账号和连接设备，正式安装包仍需用户后续验证各家登录、跨日会话、不同套餐和 Launcher 的实际行为。
