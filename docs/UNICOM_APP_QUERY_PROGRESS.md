# 联通 App 查询接入（2026-10-02）

老板要求“参考然后改进”。在已归档开源协议的基础上独立实现查询，不复制无许可证项目、固定设备伪装或上游业务代码。本轮新增功能是可选的 App 会话查询方式，不能解释为已经解决普通用户的一键短信登录。

## 使用与限制

联通卡点击连接/重新连接，或设置中选择该卡的查询方式，可选择“官方网站验证”及“联通 App 查询（试验）”。默认现有账号仍走官网。高级页可手动输入自己的 App Cookie，或 JSON 会话（token_online、同次登录的 appId/version，可携带自己的 deviceCode/deviceModel）。没有自动读取其他 App、抓包或发送验证码。Cookie 需用户逐号码确认归属；若 c_mobile/u_account 明确包含其他完整号码则拒绝。Cookie 查询成功只能证明会话能查询，不能声称号码经过服务器确认。

仅 token 会话先调用联通 onLine.htm，必须成功、返回完整 desmobile 与输入号码一致且有可用的新 Set-Cookie，再允许查询。脱敏、缺失或其他号码都拒绝，不悄悄改绑定。若卡片已填写号码，导入号码必须与其一致。密码、验证码、个人凭证不写调试日志，也不发给开发者服务。

## 实现

UnicomAppSession 与四个账号 ID 对应的 secure-storage key 隔离。选择方式保存到偏好存储，凭证仅进系统安全存储；移除展示保留会话，切换官网删除此卡 App 会话，清除本地连接删除全部四个已知 App 会话，包括隐藏账号。查询采用精确 HTTPS 联通 App 套餐和余额端点，关闭重定向，不把网页登录 Cookie 当作 App Cookie，不生成或伪造设备编号。

套餐按 resources/details 解析，精确端点无标签单位按公开参考的 MB 契约，未知显式单位不换算。零剩余不替换成总量减已用；只有剩余缺省且同单位时可计算差值。明确文本不限量不变成数字，不触发低量提醒；数字哨兵/零总量/套餐名字不用于推断无限量。重复明细去重，同名冲突阻止对应分类合计；只有名称明确写通用或定向才分类。单个未知套餐可显示“套餐余量”，多项未知不盲目合并成全部流量。

余额独立调用 accountBalancenew.htm，只读取成功响应的 curntbalancecust，按参考协议元表示；零和负数保留，缺失不视为零。余额查询失败保留成功的流量并提示话费暂未取得。

已有 Cookie 先查询，只有明确认证失败且有 token 配置时最多续期一次；业务失败、空套餐、网络异常不触发反复登录。请求每次有 15 秒上限（实际 HttpClient 内部 14 秒关闭连接）、2MB 响应限制；完整一次最多登录/套餐/续期后重查/话费四次，不无限刷新。成功续期可能轮换 token，后续套餐失败仍保存已确认的续期会话，避免丢掉新 token。

首页、前台刷新、Android 后台刷新按每个账号的模式分别执行；App 模式不创建 E5 WebView。结果复用原快照、桌面卡片和低量提醒。失败保留旧余量与旧查询时间，更新状态，不伪造新余额。查询票据、生命周期 generation、当前号码门禁阻止已切换模式、隐藏、清除或修改号码后旧回调覆盖数据。后台另确认任务仍有效、当前方式/号码及安全存储仍是此次读取的版本。

## 验证

新增套餐解析、会话客户端、导入页和主流程的合成回归。覆盖正常和零余量、未知单位、不限量、重复套餐、续期拒绝/缺新 Cookie/负 Max-Age、号码归属、独立余额失败、双联通卡分别发布组件、修改号码时丢弃旧响应。上游程序未运行，未用真实 token 或真实账号发起验证。最终测试、签名包与公开发布回执记录在 TECH_LOG 和 RELEASE_1.10.1。

真实账号首次认证、各省/套餐字段、AppID/设备校验及 Android 后台省电行为仍需设备验证。这一版本为官网查询失败提供明确的高级备选通道，不承诺四家运营商已经全部可用，不声称支持一键短信登录。
