## 必须修正的具体问题

P2：`main.dart:1748` 注册桥时捕获旧 `CarrierAccount`，`1587` 直接用其中的旧号码比较。`_editAccount` 保存后只更新账号目录，不重注册回调。真实 FlowHome 复现：打开官网时登记 `13812341234`，随后在应用内更正为 `13812345678`，官网仍上报 `138****1234`；应用继续显示“与该账号一致”，没有错误号码警告。应根据账号 ID 读取当前账号，并在身份变化时清理提示；更正号码的恢复入口必须实际生效。

P2：旧页面/旧 WebView 回调可污染新页面。`main.dart:1572` 使用 `_current(_generation)`，无法检查注册回调时的代次；接收只相信 payload 的登录 URL，没有核对当前 controller/document。真实 FlowHome 两项复现：当前已到查询页，迟到登录事件仍弹错号对话框；改选并重建账号页面后，旧 handler 同样能在新页面弹窗。应传入创建时的 generation/controller，并核验当前文档或文档身份；不能仅以账号当前可见作为旧事件门禁。

P2：提示生命周期与进度说明不一致。`page_probe.dart:155–160` 弹窗隐藏时只重置 JS `reported`，不会通知应用清除 `_loginHints`；main 开始查询和离开登录路由也没有清除提示。两项 FlowHome 用例实际失败，已经进入查询页时仍显示“官网已弹出本机号码授权框”。相同提示字符串的 Dart 去重还会抑制再次出现的同号错号提示。应显式处理隐藏/离开事件、清理正在展示的提示，并区分每次出现。

P2：掩码比对和文案过强。`carrier_web.dart:40–58` 只比较首尾数字，忽略中间公开数字与隐藏位长度；两项纯函数回归分别用 `138**9**1234` 和不等长度的登记号码复现错误 match。标准 `138****1234` 自身也无法区分 `13800001234` 和 `13899991234`，因此“与该账号一致”不能作为完整号码身份确认。应拒绝不支持的掩码或逐位核对，规范国家区号，并表述为“可见数字一致，仍请确认当前数据卡”。

P2：广电产品文案 `carrier_web.dart:17` 和进度说明把“未取得本应用可用的接入资料”写成“未向第三方应用开放”。此前契约与公开实现报告明确保留未公开商业/合作 SDK 的可能，没有取得官方拒绝开放的证明。应改为本应用尚未取得接入资料/授权，不能代运营商作是否开放的结论；当前测试对这句断言的通过不构成证据。

交付说明另有待校正项：README 本地 APK 路径现在指向1.11.1候选，紧接着仍引用1.11.0哈希说明；需明确区分公开下载与未通过验收的本地候选。构建脚本无BOM UTF8写入的代码修改合理，但旧构建日志不能当作本轮脚本成功运行回执。
