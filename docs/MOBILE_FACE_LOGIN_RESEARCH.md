# 移动“哑巴卡”与官方 App 人脸登录调查

2026-10-01。用户反馈某种移动“哑巴卡”只能在官方 App 做人脸识别。这个称呼不足以确认产品，尚未知号码归属省、正式套餐名、能否接收短信、是否因临时风控必须刷脸，也未知官方网页是否另有可用登录方式。不能把反馈推广到所有移动卡，不能承诺本应用已支持这种登录。

## 已核对的代码与公开资料

阅读 TECH_LOG.md 并复用已下载的 ChinaMobileMonitor 网页登录参考。该参考依赖浏览器手工验证码和持久化网页状态，不提供官方 App 人脸登录后向第三方授权的证据。

本应用移动登录入口为 `https://wx.10086.cn/website/bind/bindAccount/new`，查询入口为 `https://wx.10086.cn/website/spa/main/newHome`，只接收允许域上的 `getNewMarginInfo` 响应。代码位于 `app/lib/services/page_probe.dart` 与 `carrier_web.dart`。它依赖本应用自己 WebView 中已授权的官网会话，而不是中国移动 App 的私有登录态。

导航门禁只允许 HTTPS 的 `10086.cn` 与子域以及初始空白页。应用当前没有启动移动官方 App、处理其登录回调或交换用户授权票据的实现，官方 App 的自定义 scheme 也不会直接在内嵌网页中打开。这一限制不能靠放开所有 scheme 解决，必须有明确官方入口及受支持的回调契约。

登录失败时，当前主要引导是在官方页面验证、点击查询或重试，没有针对“只能官方 App 人脸认证”的独立说明。现有流程因此可能给这类用户留下可以在本应用完成验证的误解。

本次只读取公开页面，没有输入号码、验证码，没有下载 Cookie、账号响应或人脸数据。新参考保存在被忽略的 `references/mobile-face-login/`，包含来源与请求结果索引。

官方北京首页 `https://www.10086.cn/index/bj/index_100_100.html` 的“下载手厅”明确链接到 `https://www.10086.cn/cmccclient/`；该入口请求为 HTTP 200，标题“中国移动APP”，页面说明查询缴费等统一服务。可作为“前往中国移动官方 App 下载入口”的可靠 HTTPS 地址。未确认任何特定卡型的人脸准入规则，也未发现能把该 App 人脸结果授权给本应用的官方开放协议。最初尝试的 `/download/` 返回 403，不采用猜测地址。

本机无登录 HTTP 请求现有移动登录 URL 得到 HTTP 200，但 HTML 标题为“404”、正文“系统繁忙，请稍后再试”。这只是该时间和请求环境的结果，可能受入口策略、客户端条件或风控影响，不能据此断言该 URL 对所有手机失效，更不能当作人脸能力证据。

## 可实现处理

近期应为移动连接页增加明确说明：如果官网要求官方 App 刷脸，请先在官方 App 按其要求完成验证；返回本应用后仍需确认这里的官网是否允许独立登录。可以提供外部打开已确认官方 HTTPS 下载页，以及“返回后重试官网查询”。外部打开成功仅代表页面打开，不能自动把卡标记为已连接、已授权或余额已更新。这个方案改善说明与操作入口，不保证仅限官方 App 的卡能够接入。

应将无法建立官网会话的号码显示为待验证或当前登录方式暂不支持，停止持续刷新，保留此前余额及原查询时间。需要向反馈者确认正式卡型、归属省、官网实际提示和系统平台；可提供打码提示截图，但不要索取服务密码、验证码、Cookie、人脸照片或 App 抓包凭据。

真正自动接入的前提，是官网提供该号码可用的登录流程，或移动提供面向本应用的正式授权接口及回调。官方 App 的沙箱、Cookie、token 与本应用 WebView 独立，完成 App 人脸验证不等于授权给本应用。未取得这类协议前不实现私有令牌搬运、不注入官方 App，也不绕过人脸认证。系统生物识别仅证明设备本地用户，并不能替代运营商远端实名核验。

如果这种卡始终只允许官方 App 查询，本版只能如实提供官方查询指引。手动记录余额或导入用户自行取得的官方账单可另行设计为明确标注的手动数据来源，但不能称为实时查询，不应在本次未经确认直接加入。

本次仅增加研究文档和公开参考文件，不修改 Dart 或业务实现；未验证真实号码，也未证明官方人脸登录可接入。
