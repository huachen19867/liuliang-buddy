# Android 通知栏余额和快捷设置 UI

2026-10-01。读取 TECH_LOG.md，复用现有设置入口、通知授权通道和组件截图字体工具。独立组件 `app/lib/ui/system_surfaces_settings.dart` 放入 Android 提醒设置，桥接集中在 `services/system_surfaces.dart`，iOS 不挂载该组件，不调用这组原生通道。

两个开关由原生保存，页面明确“即时保存，默认关闭”。每次打开读取真实原生状态，返回前台时也重新读取。通知开启先请求已有通知权限；拒绝不保存开启。原生报告系统通知或余额频道阻断时回退关闭并说明需到手机设置开启，不能把权限请求完成当作通知已展示。

快捷设置的启用只表示入口可用。支持系统添加确认的版本在开启后请求添加，取消明确提示入口仍启用并允许重试；旧版本说明下拉编辑拖入。已添加、已存在、取消、不支持和暂不可用分别处理，没有把开关启用当作系统磁贴添加成功，也不承诺余额实时刷新。

所有异步开关操作都有 busy 门禁，关闭设置后不调用已销毁组件的 setState，也不在权限返回后继续开启已经关闭页面的功能。设置弹层改为限高可滚动，避免新增控件在小屏溢出；原有保存按钮继续负责阈值与后台周期，两个系统入口即时保存。

定向 mock 测试覆盖通知拒绝、频道关闭回退、开关持久化重读、添加取消重试、旧版手动添加和关闭页面时权限回调。iOS 页面测试补充两个 Android 开关不存在的断言。实际组件截图用例输出 `artifacts/android-system-surfaces-settings-demo.png`，使用明确 DEMO 的模拟原生状态，不是实际系统通知栏或磁贴验收。

按根任务要求，本代理不运行 Flutter/Dart/Gradle，由根统一串行格式化、测试和截图。真实系统弹窗、API26频道、API33添加确认及三星桌面行为仍需真机验证。
